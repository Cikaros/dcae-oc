## 3. 平台行为补注（新增，逐字证据见 diag-*.ts 与 events 实录）

- `ctx.session` 运行时面 = 文档 Pick 子集（setup 探针实证），**无 message 域**；REST messages/log 需 serve 密码（进程内不可得）。
- **ctx.session 域按 location 作用域**（worktree 会话对 canonical 实例不可见）——会话调用必须路由到会话所在 location 的插件实例。
- `Session.Info.outcome` 为进程内 idle/终态判定的权威（REST sessionLog SSE 只发 `log.synced` 不回放历史）。
- reviewer 正常结束且审查期间零 question/dcp 提交 = 结构性零 findings → approve（fail-closed 保持：findings 走 question/dcp 工具 → BLOCKED + inbox；异常终结 → escalate + inbox）。

## 4. 已知限制（如实声明）

1. T-9/T-12 的 LLM 依赖半项以 `--with-model` 执行（其等效语义已被 e2e 覆盖）。
2. 审查 verdict 的**文本解析**形态（1.4 §7.4 原文）依赖 REST messages——仅在有 serverUrl+密码的部署可用；进程内部署使用 §3 结构化判定（后备，1.4 §3 使用规则允许）。
3. `dcae promote` 依赖全局门禁表（fixture `global: []` 直通）。
4. Windows 下 PS5 不得用于生成/改写 opencode.json（塌缩数组 + BOM 风险）——一切配置写入走 initProject。
